## Managed shared launcher dispatch

dot_local/bin/executable_mesh-plus.tmpl:17-44 parses --source with the CLI's normal last-value semantics before importing Mesh or a domain facade. For serve/bridge, it dispatches tmux_default to the dedicated full-view mesh-plus-tmux launcher; agent_active to the fixed a7/a23 active launcher; and agent_working_set plus host-declared agent_working_set_<profile> values to the fixed a8/a24 launcher. Each specialized wrapper binds its allowed source/profile (executable_mesh-plus-tmux.tmpl:10-16, executable_mesh-plus-active.tmpl:10-16, executable_mesh-plus-working-set.tmpl:11-23). Other Agent serve/bridge calls use the generic full route pinned by bridgeSelection (a5/Mesh a20) and load the Agent full publisher only when that selection's role is publisher (executable_mesh-plus.tmpl:47-67). Ordinary diagnostics/read commands remain on the generic selected Mesh role. The working-set wrapper allows only manifest-declared sources and fixes the 72-hour window; current checks render these routes and exercise dispatch/source separation (scripts/check-agent-active-feed, scripts/check-agent-working-set, scripts/check-agent-home-profiles).

The active/working-set wrappers are additive alongside the full route, not evidence that full reads or feed availability can be removed. The effective dashboard selector is host override plus the shared launcher/unit selection, not the top-level fallback values in deployments/rlcd-agent-dashboard.json alone.
