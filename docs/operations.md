# Releases and operation

The [0.1.0a25 prerelease](https://github.com/byebyebryan/mesh-plus/releases/tag/v0.1.0a25)
is published with immutable assets and provenance. It withdraws the standalone
Agent active-only profile while retaining full Agent, working-set, Tmux and
Host Mesh interfaces. Working-set continues to cover active membership.

The [public-delivery closeout](evidence/2026-10-23-public-delivery/README.md)
records asset hashes, public-download checks and scoped managed convergence.
It is dated acceptance, not proof of a fresh host/runtime check.

## Independent selections

Collector/read/publisher, full/working-set feed, Tmux reader/bridge, dashboards
and SSH authority can retain different reviewed versions. The
[deployment owner](https://github.com/byebyebryan/dotfiles/tree/main/deployments)
records effective role selections and controls. The a9/a25 Agent collector and
working-set cohort does not select a25 for every other role.

Source main, release build source, qualification commit and installed package
can differ. Follow immutable artifact provenance rather than rebuilding an old
version from today's docs head. A documentation commit changes no native service.

## Diagnostics and recovery

`mesh-plus doctor` reports installed package metadata. Source-specific diagnostic
flags inspect the selected descriptor without creating a provider adapter;
see `mesh-plus doctor --help` and [SDK diagnostics](sdk-diagnostics.md).

Change only the intended role's reviewed configuration/artifacts. Preserve
directional authority, exact source/host binding, paired rollback inputs and
independent Observer factories. Verify selected bytes, readiness and recovery
separately from a source gate. No optional transport is selected by installation.

Ordinary readers retain complete-view delivery. Optional WSS and view-feed
adoption have independent consumer gates. Delta-sync remains dark after failed
CPU/capacity qualification; old G1 plans do not resume that work.

[Historical delivery records](history/README.md#delivery) and
[dated evidence](evidence/) retain exact earlier pins, measurements and failures.
Use their own checkpoint boundaries instead of combining old commands into
a current deployment recipe.
