# Agent active-plus-recent working-set profile

This additive source candidate follows the separately approved working-set
implementation scope. Source/schema review, isolated package qualification and
operational adoption are separate gates. Existing normal roles remain selected.

The explicit profile `agent-observer.mesh-working-set.v1` carries native
`agent-observer.working-set` version 1 through SDK 1, Read 1, preparation 1 and
Delivery 1. It adds no transport capability or generic API. Full Agent v1/v2/v3,
active v1, Tmux and every earlier normative schema retain their exact bytes,
defaults and meanings. There is no automatic full/active fallback or format
sniffing. A trusted factory binds host, source, socket and one immutable window.

## Selection, clocks and coverage

Observer owns `E AND (A OR R)`: eligible current active rows or eligible recent
conversation activity, with a default 72-hour window and zero disabling R.
Active selection does not require a known/recent activity age. Recent selection
may retain parked or unknown runtime without creating a running assertion.
All selected rows preserve the frozen API4 body meaning. Full history remains
an explicit independently supported route.

Exact native selector bytes/digest and configured-window equality are mandatory
owner admission checks. The packaged schema describes the reviewed window
family, not an active-only fixed digest or an arbitrary remote predicate.
Original service/boot/time-domain, source context, sample and accepted-receipt
joins remain mandatory. Only accepted canonical worker brackets supply recency
clock authority. Monotonic K and last-T guards survive nonterminal gaps, scope
retirement and capacity changes under the original clock-incarnation rules.
Current-bracket Dhi stays independent; positive receipt attenuation never proves
a negative. Original current census and all supporting decisions are required
for complete coverage, including complete-empty.

The pure Observer facade calls the public guard's current-time check before
context, evaluates the independent active/recent alternatives and masks each
field against its original receipt. Generic required-receipt bookkeeping remains
conjunctive; it cannot implement the domain OR. Positive expiry without an
admitted negative makes membership unresolved and coverage partial. Omission,
refusal, disconnect and old context never prove absence or provider deletion.

## Compact receipt metadata and independent admission

Each scope owns a frame-local canonical `supportTable` of complete eight-field
FactSupport objects. The reviewed typed positions contain exact integer indices
or their existing nullable value. Deduplicate by the whole original map, retain
support-array order/multiplicity, and preserve historical uncertainty separately
from current receipt requirements. At most 8,194 distinct table entries cover
two historical references per 4,096 uncertain identities plus two current
component maps; that structural ceiling grants no extra storage budget.

The packaged structural schemas enforce closed shapes, typed positions,
nullability, static bounds and lengths. The public profile additionally sets
`uniqueItems` on each support table to reject duplicate complete JSON maps
independently; native admission enforces the same uniqueness and stricter order
semantics. Pure native admission additionally
requires `type(index) is int`, actual enclosing-table bounds, exact canonical
uniqueness/order, no unused entries and all original support/clock/selection
semantics on direct, bridge and reconstructed public routes. An integral float
passing Draft202012's integer check is still invalid. Object equality alone is
not no-coercion or canonical-byte roundtrip proof.

NativeState retains the exact compact scope/table with original service fields
and untouched selected records. Public preparation accepts immutable mappings
and tuples, resolves one current entry and emits detached existing rules.
Neither a complete expanded metadata roster nor a private Mesh graph is needed.
Restore must reproduce the exact compact frame and canonical bytes. An index
never escapes alone or resolves against a replacement generation's table;
detached results and historical ledgers own their actual full-support copies.

## Ownership, bounds and delivery

Keep 4,096 identities, the combined 1 MiB scope/clock/decision bound, the
8 MiB plus 16 KiB native frame, 32 receipts per host and all existing service
client/shared encoded and Mesh queue/metadata bounds. Table maps, canonical keys,
containers, reference cells, scratch, current/new generations, historical state,
copies and failed/cancelled work remain funded through actual retirement. Equal
values do not prove shared physical allocation; smaller JSON does not prove
heap/RSS savings. No cap or estimate exception is introduced.

Snapshot/proof/subscribe retain original host/source/profile/epoch, native
digest, unpredictable nonce, full RTT subtraction, margin and deadlines. Fresh
post-nonce acquisition is mandatory. Heartbeats, cache reads, reconnections,
reencoding and projection timers cannot renew native facts or conversation
activity. Failure visibly revokes affected authority without evicting healthy
siblings or returning a silently truncated complete view.

## Qualification boundary

The new exact native/request/profile schema references and their packaged copies
are reviewed together under an additive lock extension. Every preceding
normative digest remains exact. The descriptor's contract digest hashes the
Mesh profile schema, independently of the native-frame hash. Source/factory
registration alone is not an installed-pair or producer acceptance claim.

Acceptance requires actual public Reader/preparation/facade proof and gap/expiry
tests, malformed/coercible references, exact native restoration, immutable-window
and foreign-binding rejection, original full/active/Tmux regression, refusal and
retained-error/cancellation ownership, matched CPU/wire and capacity/resource
qualification, isolated IPC/fixed SSH and independently verified native/installed
pairs. Arithmetic support-table models and failed partial 2,000-row prefixes
remain their original evidence. Deployment, client adoption and physical device
checks retain separate authorization. Delta synchronization remains dark.
